# G-OS Dock — GNOME Shell 51

G-OS Dock is a GNOME Shell extension written in TypeScript and compiled to JavaScript. All editable source files are stored directly in this repository; the installable ZIP is generated by the build and is not committed.

## Features

- One dock view per monitor, sharing GNOME's favorites list and ordering.
- Favorites and running applications.
- Bottom, top, left, and right positioning.
- Per-monitor edge sensor, auto-hide, and smart-hide.
- Acrylic-like translucent styling (CSS transparency, not compositor backdrop blur).
- Running indicators, focused-app highlight, and optional window-count badges.
- Application context menu for window selection, launch, minimize/close, pin/unpin, and favorite ordering.
- Configurable icon size, spacing, theme, and hover magnification.
- Optional hover window previews with live compositor thumbnails, titles, and click-to-focus (configurable in preferences).
- Drag-and-drop reordering of pinned favorite applications, with live drop-target highlighting and synchronized ordering across monitors.
- Preferences through GNOME Extensions.

## Requirements

- GNOME Shell 51 (Wayland or X11; runtime testing on a real GNOME 51 session is still required).
- Node.js 20+ and npm.
- `glib-compile-schemas` and `zip` for packaging.

## Build

```sh
npm install
npm run check
npm run pack
```

The build creates `g-os-dock@cgreg21.github.io.zip`, containing compiled JavaScript, metadata, stylesheet, and the compiled GSettings schema.

## Install locally

```sh
gnome-extensions install --force g-os-dock@cgreg21.github.io.zip
gnome-extensions enable g-os-dock@cgreg21.github.io
```

Or use `scripts/install-local.sh`. To uninstall, use `scripts/uninstall-local.sh`.

## Local development environment

G-OS Dock includes an isolated **nested GNOME Shell** development session. It opens GNOME Shell in a separate window with its own D-Bus session and private XDG configuration/data directories. It does not replace or modify the user's main GNOME session or its extension settings.

### Host requirements

- A Linux desktop session with GNOME Shell 51 installed (the nested session uses the host's installed GNOME Shell version).
- Node.js 20+ and npm.
- `dbus-run-session`, `gnome-shell` **51.x**, `gnome-extensions`, `gdbus`, `timeout`, `inotifywait` and the existing build tools (`zip`, `glib-compile-schemas`).

Install the missing tools using your distribution package manager. For example:

```sh
# Fedora
sudo dnf install gnome-shell inotify-tools dbus-daemon nodejs npm zip glib2

# Ubuntu/Debian
sudo apt install gnome-shell inotify-tools dbus-daemon nodejs npm zip libglib2.0-bin
```

Then install project dependencies and launch the environment:

```sh
npm install
npm run dev
```

The launcher verifies that the host provides GNOME Shell 51.x, creates a private profile under `~/.local/share/g-os-dock-dev`, starts GNOME Shell nested on Wayland (or X11 when the host session is X11), waits for the Shell D-Bus service, then builds and installs the extension.

### Automatic rebuild and reload

While `npm run dev` is running, edits to `src/`, `schemas/`, `metadata.json` or `stylesheet.css` trigger this sequence:

1. TypeScript compilation and schema compilation.
2. Creation of the installable extension ZIP.
3. Installation into the private GNOME profile.
4. Disable/enable cycle to reload G-OS Dock in the nested Shell.

A failed build leaves the last successfully installed extension running. Press Ctrl+C in the terminal to stop the development session. The private profile can be removed independently with:

```sh
rm -rf ~/.local/share/g-os-dock-dev
```

To use another private profile location, set `G_OS_DOCK_DEV_HOME` before running `npm run dev`.

**Note:** this is a nested GNOME Shell session, not a complete virtual machine. It isolates the Shell session and extension settings while using the host's GNOME Shell binaries and graphics stack. Test on an actual GNOME 51 installation for final compatibility validation.

## Publish

Build and test the extension in a GNOME Shell 51 session, then upload the ZIP at https://extensions.gnome.org/upload/. Publication remains subject to GNOME Extensions review.

## Limitations

The acrylic effect currently uses translucent CSS only. GNOME Shell's public extension APIs do not expose a general backdrop-blur API for arbitrary extension actors. Window tracking, menu behavior, and monitor handling still require runtime validation on GNOME Shell 51.
