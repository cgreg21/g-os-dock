# G-OS Dock — GNOME Shell 51

G-OS Dock is a GNOME Shell extension written in TypeScript and compiled to JavaScript. All editable source files are stored directly in this repository; the installable ZIP is generated by the build and is not committed.

## Features

- One dock view per monitor, sharing GNOME's favorites list and ordering.
- Favorites and running applications.
- Bottom, top, left, and right positioning.
- Per-monitor edge sensor, auto-hide, and smart-hide.
- Acrylic-like translucent styling (CSS transparency, not compositor backdrop blur).
- Running indicators, focused-app highlight, and optional window-count badges.
- Application context menu for window selection, launch, minimize/close, pin/unpin, and favorite ordering.
- Scroll over an application with multiple windows to cycle focus; middle-click an application to open a new window.
- Keyboard navigation between dock applications (arrow keys, Home/End), opening window previews with the inward arrow, Escape to close previews and return focus, visible focus state, and accessible application names.
- Configurable icon size, spacing, theme, and hover magnification.
- Optional hover window previews with live compositor thumbnails, titles, and click-to-focus (configurable in preferences).
- Window preview rendering and lifecycle are isolated in `src/windowPreviews.ts`; `src/dockView.ts` delegates preview operations to this module.
- Application context-menu construction and cleanup are isolated in `src/appContextMenu.ts`.
- Minimize or close individual windows directly from their preview cards; show each window's workspace and jump to another workspace from its preview.
- Drag-and-drop reordering of pinned favorite applications, with live drop-target highlighting and synchronized ordering across monitors.
- Hides GNOME's built-in Overview Dash while G-OS Dock is enabled, and restores it when the extension is disabled.
- Preferences through GNOME Extensions.

## Requirements

- GNOME Shell 51 (Wayland or X11; runtime testing on a real GNOME 51 session is still required).
- Node.js 20+ and npm.
- `glib-compile-schemas` and `zip` for packaging.

## Source architecture

The extension source is organized by responsibility. The main dock view coordinates the feature modules rather than implementing every interaction itself.

```text
src/
├── dock/
│   ├── manager.ts
│   └── view.ts
├── features/
│   ├── app-item.ts
│   ├── appearance.ts
│   ├── context-menu/
│   │   └── index.ts
│   ├── drag-and-drop.ts
│   ├── indicators.ts
│   ├── keyboard-navigation.ts
│   ├── layout.ts
│   ├── visibility.ts
│   ├── window-previews/
│   │   ├── card.ts
│   │   └── index.ts
│   └── window-tracker.ts
├── preferences/
│   ├── appearance.ts
│   └── general.ts
├── types/
│   ├── gnome-shell-dnd.d.ts
│   └── gnome.d.ts
├── extension.ts
└── prefs.ts
```

Each feature owns its own behavior and cleanup. `dock/view.ts` wires the modules together; preferences are split by settings group. Keep new code close to the feature it implements, prefer small functions and explicit dependencies, and avoid introducing abstractions that do not simplify the code.

## Build

```sh
npm install
npm run check
npm run pack
```

The build creates `g-os-dock@cgreg21.github.io.zip`, containing compiled JavaScript, metadata, stylesheet, and the compiled GSettings schema.

## Install locally

```sh
gnome-extensions install --force g-os-dock@cgreg21.github.io.zip
gnome-extensions enable g-os-dock@cgreg21.github.io
```

Or use `scripts/install-local.sh`. To uninstall, use `scripts/uninstall-local.sh`.

## Local development environment

G-OS Dock includes an isolated **nested GNOME Shell** development session. It opens GNOME Shell in a separate window with its own D-Bus session and private XDG configuration/data directories. It does not replace or modify the user's main GNOME session or its extension settings.

### Host requirements

- A Linux desktop session with GNOME Shell 51 installed (the development session uses the host's installed GNOME Shell version). For GNOME 49 and later, install the Mutter Development Kit (`mutter-devkit` on CachyOS/Fedora, `mutter-dev-bin` on Ubuntu/Debian). GNOME 48 and earlier use the legacy `--nested` backend.
- Node.js 20+ and npm.
- `dbus-run-session`, `gnome-shell` **51.x**, `gnome-extensions`, `gdbus`, `timeout`, `inotifywait` and the existing build tools (`zip`, `glib-compile-schemas`).

Install the missing tools using your distribution package manager. For example:

```sh
# Fedora 45 (recommended)
bash scripts/install-dev-deps-fedora.sh

# Or install the Fedora dependencies manually
sudo dnf install gnome-shell gnome-session mutter-devkit inotify-tools dbus-daemon nodejs npm zip glib2

# Ubuntu/Debian
sudo apt install gnome-shell mutter-dev-bin inotify-tools dbus-daemon nodejs npm zip libglib2.0-bin

# CachyOS
bash scripts/install-dev-deps-cachyos.sh
```

On Fedora 45, `scripts/install-dev-deps-fedora.sh` installs the required host tools with `dnf` (GNOME Shell 51, GNOME Session, Mutter Devkit, D-Bus, GLib, Node.js/npm, inotify-tools and ZIP). You can also run it with `npm run dev:install:fedora` after cloning the repository.

On CachyOS, the helper installs the host tools with `pacman` (GNOME Shell,
GNOME Session, Mutter Devkit, D-Bus, GLib, Node.js/npm, inotify-tools and ZIP). It does not
change your desktop session or graphics drivers. The same GNOME 51.x version
check applies; if the rolling repositories have not yet provided GNOME 51,
the development launcher will stop rather than silently testing against a
different Shell version.

Then install project dependencies and launch the environment:

```sh
npm install
npm run dev:check
npm run dev
```

Run `npm run dev:check` at any time to validate the host dependencies and versions. The launcher performs the same checks automatically, verifies that the host provides GNOME Shell 51.x, and creates a private profile under `~/.local/share/g-os-dock-dev`, starts GNOME Shell in the Mutter Development Kit on GNOME 49+ (or the legacy nested backend on older versions), waits for the Shell D-Bus service, then builds and installs the extension.

### Automatic rebuild and reload

While `npm run dev` is running, edits to `src/`, `schemas/`, `metadata.json` or `stylesheet.css` trigger this sequence:

1. TypeScript compilation and schema compilation.
2. Creation of the installable extension ZIP.
3. Installation into the private GNOME profile.
4. Disable/enable cycle to reload G-OS Dock in the nested Shell.

A failed build leaves the last successfully installed extension running. Press Ctrl+C in the terminal to stop the development session. The private profile can be removed independently with:

```sh
rm -rf ~/.local/share/g-os-dock-dev
```

To use another private profile location, set `G_OS_DOCK_DEV_HOME` before running `npm run dev`.

**Note:** this is a nested GNOME Shell session, not a complete virtual machine. It isolates the Shell session and extension settings while using the host's GNOME Shell binaries and graphics stack. Test on an actual GNOME 51 installation for final compatibility validation.

## Publish

Build and test the extension in a GNOME Shell 51 session, then upload the ZIP at https://extensions.gnome.org/upload/. Publication remains subject to GNOME Extensions review.

## Limitations

The acrylic effect currently uses translucent CSS only. GNOME Shell's public extension APIs do not expose a general backdrop-blur API for arbitrary extension actors. Window tracking, menu behavior, and monitor handling still require runtime validation on GNOME Shell 51.
